# 1.3.1 检查状态与预览提示

验收：文件检查异常与缩略图失败明确区分，鼠标悬停列表不再弹出完整路径和多行技术诊断；选中行仍能查看、复制原始诊断。

1. 原“读取失败”改为“文件检查异常”，状态列改“处理状态”。该状态原本同时涵盖无法读取、未知校验警告、结构校验失败，并非专指图片无法解码或缩略图加载失败。
2. 关闭列表原生整行长Tooltip；选中异常行后在底部显示中文说明及技术信息，复制详情和问题CSV仍保留原始诊断。
3. 缩略图与文件检查状态独立。元数据检查未通过的图片，如预览解码成功仍显示真实缩略图；预览失败才使用失败占位图。预览不改变文件检查/标签状态，也不放宽写入校验。
4. 预览失败仍写WARNING，选中后提示“缩略图暂不可用”。原有标签错误和恢复路径不被预览错误覆盖。

原因：1.3.0把未知EXIF规范警告与真实读取错误统一显示为“读取失败”，并用同一状态强制缩略图显示失败占位图；完整路径和原始诊断放在整行Tooltip中，导致用户把标签检查与图片预览混淆且浮窗遮挡列表。

不根据图片可预览就推断原文件完整或可安全写入；未知校验警告仍停止写入。美工现场远程SMB原问题仍未复现。

2026-10-17只读核对用户授权测试空间中的两张相关JPEG：ExifTool退出0、无Error，两张均有13条EXIF规范警告（包括非标准IFD0项、条目顺序、ExifOffset顺序）；内存快照经GDI完整绘制成功，实际均1600×1600，原图读取前后SHA-256一致。这能确认这两张的提示来自校验拦截，不能单凭该提示认定像素已损坏。未对原图写入标签或修改元数据。

修复验证：WinPS5.1 UI回归确认关闭列表长浮窗、中文解释和原始诊断保留；真实可解码但检查状态异常的图片仍显示真实预览，状态及原图不变；预览超时提示与标签原因分开，暂停/恢复/清空仍释放资源。22项启动/打包测试通过，517条payload与源码一致，隔离提取后运行成功。

## 1.3.2 详情改用日常用语

用户反馈原始诊断仍太长。详情现在优先显示简短中文原因、处理结果和下一步操作，文件位置放在最后。例如：

> 图片附带信息不规范，本次已跳过打标签。
> 可用图片编辑软件另存一份副本后再试。

分别说明空文件、疑似内容不完整、文件占用、权限不足、连接异常；未知原因提示导出诊断包，不猜测文件已损坏。已有恢复副本时优先提示不要删除或重复处理，并保留完整恢复位置。底部及“复制详情”不再直接展示底层英文告警，原始信息仍保留在诊断日志、内存状态及问题清单中。预览失败单独提示“预览暂时无法显示”。
