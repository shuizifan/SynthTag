# SynthTag 1.1.0 实施与验收

目标：共享文件夹批量写标签出现任何读取、写入、替换或验证异常时，逐文件显示失败及原因；提供本地分级日志、近30天清理和设置中的诊断包导出；标题为 `SynthTag（打AI标签） v1.1.0`，同步现有 GitHub 仓库。

## 已验证的事实

- 2026-10-17，本地 `main` 与 `origin/main` 一致，原版本提交为 `d822466`（1.0.0），工作区无已跟踪改动。
- 旧 `Invoke-ExifTool` 忽略退出码，后续回读覆盖写入时的 stderr；`Get-Subjects` 将带 `Error` 的 JSON 当成成功且标签为空。使用 `File is empty` 样本已复现误判。
- 截图中 `_exiftool_tmp` 表明存在 ExifTool 临时文件；尚无美工现场 SMB 日志、原始损坏文件，无法断定具体断线/权限/占用原因。
- 本机附带 ExifTool 13.59，支持 `ImageDataHash`（图片/视频数据摘要），本机 Windows UNC 管理共享可用于隔离样本测试。

## 设计与工作包

1. `metadata.ps1`：ExifTool返回退出码、stdout、stderr；错误JSON不可当成成功；在本地工作副本写标签并验证格式、标签及图像/视频数据摘要；上传到目标目录独立临时文件，flush并校验SHA256后以带备份的 `File.Replace` 提交，回读验证后清理本次备份。禁止覆盖或删除既有 `_original`/`_exiftool_tmp`。提交异常保留本地原始副本供恢复，不采用先清空原图再复制的降级路径。
2. `runtime.ps1`：`%LOCALAPPDATA%\SynthTag\Logs` 按日分级日志，保留今天及前29天；诊断ZIP含基本环境、版本、日志、用户列表中的问题状态，不含图片和环境变量全集。
3. `app.ps1`：标题版本、设置和导出诊断入口、异常详情和工具提示、统一失败统计，操作期间禁止关闭与重入。
4. `build/`：打包新增模块、版本资源、本机缓存隔离、启动器严格检查解压错误；构建新版EXE。

## 验证计划

- 回归：中文/空格/方括号路径，PNG/JPEG/TIFF/WebP，添加/重复归一/移除，其他关键词不丢失。
- 故障：空文件、CRC损坏、只读、独占锁、既存备份和旧临时文件、模拟ExifTool失败及替换失败；验证失败不报成功且原始数据仍在。
- UNC：仅对自建样本通过本机SMB共享执行写入验证，不操作用户图片。
- 日志：分级、日期边界、运行时清理、诊断ZIP内容、写日志失败提示。
- Windows PowerShell 5.1语法、源码启动与单文件包内容/启动、独立代码审查及Git敏感文件检查。

## 边界与恢复

本次不自动修复历史损坏图片，不自动删除旧临时文件，不上传诊断包。故障恢复副本可能含原图，仅本机保存，诊断包不包含这些文件。网络存储不支持安全替换时明确失败；不保证服务器断电/存储硬件故障下的持久性。现场共享文件夹仍需新版本实际批量复测。
