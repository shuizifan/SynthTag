# 共享目录问题排查（2026-10-17）

## 已确认

- 用户截图出现 `文件.png_exiftool_tmp`，这是 ExifTool 写入阶段使用的临时名称。仅凭缩略图/图标不能证明原图与临时文件都已永久损坏，需要检查实际文件。
- 旧程序没有读取 ExifTool 退出码；后续标签回读覆盖写入时的 stderr；带 `Error` 的 JSON 可能进入“成功读取、无标签”映射；成功条件只验证标签，没有验证图像内容。旧程序也静默清理 `_original`，可能失去有用的恢复材料。
- 本项目附带 ExifTool 13.59 的 `exiftool_files/exiftool.pl` 写入流程：创建 `_exiftool_tmp`，原图重命名为 `_original`，临时文件再重命名为原路径；部分失败分支会报 `Error renaming temporary file` 并保留临时文件。`lib/Image/ExifTool/Writer.pl` 也包含部分文件系统不允许重命名覆盖时先删除旧目标、再重命名的分支。
- 当前电脑无法访问美工发生故障的远程 SMB 共享，不能确认现场的具体触发原因。

## 推测（按与现象的吻合程度）

1. **重命名或替换被占用/权限拒绝**：资源管理器预览、图片编辑器、另一个用户、杀毒软件可能持有不允许删除共享的句柄；共享/NTFS权限允许写入却不允许删除或替换。写临时文件成功并不意味着重命名能够成功，符合残留 `_exiftool_tmp` 的现象。
2. **临时文件提交期间中断**：SMB断线、NAS响应慢、程序被强制结束、客户端/服务器缓存尚未完成提交，会使临时文件或备份遗留。没有现场日志不能确定是哪一种。
3. **多个客户端同时处理同一文件**：读回的路径可能已经被别的进程替换；旧程序缺少前后图像数据校验与并发变化检测，因此“已含标签”不足以证明本次写入完全成功。

## 新版本的处理

ExifTool只修改本机副本；本地媒体校验、图像/视频内容SHA-256、目标完整文件SHA-256和标签回读通过后才报告成功。每文件有退出码、stderr、阶段日志和明确的错误状态，提交异常保留本机原始副本及恢复记录，既存历史临时/备份文件不自动清理。

PNG逐块CRC检查覆盖ExifTool略过的IEND等边界；JPEG的已知非像素EXIF/IPTC规范警告单独记录，不能让首条无害警告掩盖后续截断/损坏警告。

本机SMB/UNC和故障注入测试验证了失败处理。网盘挂载测试可检查另一种Windows文件系统驱动的兼容性，但不能作为远程SMB现场故障已解决的证据。

实际网盘挂载测试中，PNG/JPEG各6张副本完成添加、备份、移除和内容校验。另发现并修正：替换成功后旧读取句柄已指向备份，若直到整个操作结束才释放，Dokan可能在删除备份时等待约一分钟并返回拒绝访问；现在在替换返回后立即关闭旧句柄。该现象是挂载环境中的实测结果，不能据此断定共享目录现场同根因。

## 现场复测时需要的材料

使用1.1.0处理一批副本；若失败，保留原图、所有临时/备份文件和软件提示的恢复目录，立即在设置中导出诊断ZIP。ZIP不包含图片/恢复副本，它们需另行人工选择是否提供。结合每文件的替换阶段、原生错误码、退出码、校验摘要、共享存储类型和发生时间，才能进一步区分占用、权限、中断和源文件异常。
